# 16 · 상황 사전: "이럴 땐 이렇게" (AIP)

00 이 "무엇을 쓸까"라면 이 문서는 "이 상황이 왔는데 어떻게 하지"다. A~H 는 범용, **I~M 은 AIP 제품 상황**이다. 여기서 답이 나오면 다른 문서를 열 필요가 없다.

## A. 글자

| 상황 | 이렇게 |
|---|---|
| 제목이 두 줄 | 허용(`text-wrap: balance` 가 균형을 잡는다). 세 줄이면 문구를 줄인다 |
| 사이드바 항목 이름이 길다 | 두 줄까지 허용(최소 높이 32 에서 늘어난다). 폭은 안 늘린다 |
| 경로·타입이 길다 | 모노 그대로 줄바꿈(`overflow-wrap: anywhere`). 말줄임으로 정보를 숨기지 않는다 |
| 문서에 h5 가 필요 | 없다. 구조를 다시 짜거나 페이지를 나눈다 |
| 본문 안 강조 | `**굵게**`(600). 형광펜은 페이지당 한두 번 |
| 12px 보다 작게 | 없다 |
| 영어 대문자 라벨 | `.aip-eyebrow`(모노). 일반 sans 대문자 라벨은 만들지 않는다 |
| 숫자 열 | `.aip-table__num` 또는 `.aip-numeric` |
| 함수·파라미터 이름이 문장 안에 | 인라인 코드 |

## B. 색

| 상황 | 이렇게 |
|---|---|
| 브랜드색 글자가 필요 | `text.brand`(blue.700). 원색 #1C77C3 은 버튼 면이다 |
| 탱저린·노랑 글자를 쓰고 싶다 | 흰 면에서는 불가. 노랑은 `<mark>`, 탱저린은 경고 면. 코드 면 위에서만 글자가 된다 |
| 경고를 노랑으로 | 아니다. 경고는 탱저린(`status.warning`). 노랑은 강조 |
| "중요한 정보"를 빨강으로 | 위험이 아니면 IMPORTANT(노랑) |
| 성공을 파랑으로 | 초록. 파랑은 정보·브랜드 |
| 한 화면 색이 넷 | 중립 + Blue + (상태 하나 또는 형광펜). 다이어그램·코드는 예외 |
| 큰 면을 색으로 칠하고 싶다 | `subtle`·`brand-subtle`. 진한 Blue 면은 랜딩 CTA 띠 하나 |
| 다크에서 Blue 버튼이 어둡다 | 의도다. 두 테마 같은 AIP Blue 가 브랜드를 지킨다 |

## C. 레이아웃·간격

| 상황 | 이렇게 |
|---|---|
| 13·18px 이 필요 | 12·16. 스케일 밖은 없다 |
| 문서 본문이 좁아 보인다 | 720 이 맞다. 넓은 표·그림만 래퍼 안에서 스크롤 |
| 1280 에서 TOC 때문에 본문이 650 | 허용. 그 아래는 TOC 가 본문 위 접힘으로 간다 |
| 모바일에서 사이드바 | 상단 바의 Menu → 드로어 |
| 표가 넘친다 | `.aip-table-wrap`(표만 스크롤, tabindex 0) |
| 폼 필드 둘을 나란히 | `.aip-grid--2`(모바일 1열) |
| 그리드 마지막 줄 빈 칸 | 그대로 |

## D. 모양·깊이

| 상황 | 이렇게 |
|---|---|
| 카드에 그림자 | 없다. 링크 카드 hover 만 `shadow.sm` |
| 코드 블록이 떠 보이게 | 아니다. 홈 히어로 목업만 `shadow.lg` |
| 반투명 유리 헤더 | 없다. 불투명 + 하단선 |
| 배경이 심심하다 | 점 격자(히어로·다이어그램·빈 Playground). 그 외에는 여백이 답 |
| 둥글게 하고 싶다 | 카드 8, 다이얼로그 12 가 끝 |

## E. 컴포넌트 조합

| 상황 | 이렇게 |
|---|---|
| primary 둘 | 하나는 secondary |
| 버튼인데 링크처럼 생긴 것 | 이동이면 `<a class="aip-link">`, 동작이면 ghost 버튼 |
| 카드 전체 클릭 + 안에 버튼 | 둘 중 하나 |
| 탭 안에 탭 | 없다. 세그먼트 또는 페이지 분리 |
| 값 고르기에 Dropdown | 네이티브 Select. Dropdown 은 행동 목록 |
| 아이콘 버튼에 툴팁 | 넣는다. 문구 = aria-label |
| 배지가 넷 | 셋까지. 나머지는 본문으로 |
| 콜아웃 연속 셋 | 문서 구조 문제. 하나로 합치거나 본문으로 |

## F. 상태

| 상황 | 이렇게 |
|---|---|
| 300ms 안에 끝나는 로딩 | 아무것도 표시하지 않는다 |
| 버튼 로딩 | `aria-busy="true"` + `disabled`. 폭 유지 |
| 비활성 버튼의 이유 | `aria-disabled="true"` + 툴팁 |
| 검색 0건 | `.aip-search__empty` 에 입력어 + 제안 |
| 복사 성공 | 버튼이 1.6초 "Copied" + 알림. 토스트 없음 |
| 생성 성공 | 그 자리 `.aip-status--success` |

## G. 접근성

| 상황 | 이렇게 |
|---|---|
| 포커스 링이 디자인을 해친다 | 지우지 않는다. 촘촘한 곳은 안쪽으로 |
| 아이콘만 있는 버튼 | `aria-label` |
| 장식 이미지 | `alt=""` |
| 그림으로 흐름 설명 | 텍스트 설명(`details.aip-diagram__text`) 필수 |
| 스크롤 컨테이너 | `tabindex="0"` + 이름(`aria-label`) |

## H. 다크

| 상황 | 이렇게 |
|---|---|
| 다크에서만 색을 바꾸고 싶다 | 컴포넌트에서 분기 금지. 시맨틱 토큰의 다크 값을 고친다(14 §2) |
| 히어로 글자가 다크에서 뒤집힌다 | 이미지 위 글자는 원시 `base.white` 로 고정 |
| 로고가 어둠에 묻힌다 | inverse 락업 |

## I. 문서 작성(사람·AI 공통)

| 상황 | 이렇게 |
|---|---|
| 같은 예제를 TS·Python 둘 다 | Code Tabs + `data-aip-sync="language"`, 값 `ts`·`py` |
| 셸 명령 | `.aip-code__prompt` 로 `$`. 복사에서 빠진다 |
| 바뀐 줄을 보여주기 | `data-diff="+"`/`"-"`. 바뀐 이유는 본문에 |
| 한 줄을 짚기 | `data-highlight`. 블록당 세 줄까지 |
| 정의를 쓴다 | Spec block(`dl`). 산문으로 정의하지 않는다 |
| 함수 인자 | Parameter rows. 표 대신 |
| "이렇게 하면 이렇게 된다" | Example block(입력 + Result) |
| 필수 단어(MUST) | `.aip-rfc` |
| Markdown 으로만 쓴다 | `> [!NOTE]` 등 GFM alert, 펜스 코드에 언어 표시. prose 가 같은 모양으로 받는다 |
| 페이지 요약 | `.aip-doc-lead` 한두 문장. 에이전트가 여기서 요지를 읽는다 |
| 앵커 id | 영문 kebab, 문구가 바뀌어도 유지 |

## J. AIP 개념을 그림으로

| 상황 | 이렇게 |
|---|---|
| Intent → Runtime → Data 를 한 줄로 | `.aip-flow` |
| 서버 경계·거부 경로가 있다 | SVG + `.aip-svg-zone` + `data-edge="reject"` |
| README·PR 에 그림 | Mermaid + `dist/diagram.mermaid.json` classDef |
| 개념이 표에 없다(예: Queue) | 가장 가까운 개념(external 또는 data)으로. 늘려야 하면 14 §2 |
| 강조할 경로가 둘 | 그림을 둘로 |

## K. MakeAIP

| 상황 | 이렇게 |
|---|---|

## M. AIP 가 아직 정하지 않은 것

| 상황 | 이렇게 |
|---|---|
| 예제에 AIP 문법이 필요 | "illustrative" 라벨을 붙이고, 디자인 시스템 문서에서 문법을 정본처럼 쓰지 않는다 |
| 라이선스 표기 | "License to be decided" |
| 제품 기능 이름이 바뀐다 | 토큰·클래스 이름은 개념어(intent·runtime·permission)라 영향 없다. 예제 문구만 바꾼다 |
