# 18 · 설계 결정과 자기 검토 기록 (AIP v1.0.0)

명세가 요구한 순서(방향 → 토큰 구조 → 타이포 → 색 → 컴포넌트 구조)대로 결정했고, 단계마다 실제 렌더(Chrome, 라이트·다크·390px)로 확인했다. 아래는 결정과 그 근거, 그리고 검토에서 고친 것이다.

## 1. 결정 요약

| 영역 | 결정 | 버린 대안과 이유 |
|---|---|---|
| 방향 | 제도 용지 위의 청사진: 흰 종이 + Charcoal 잉크 + Blue 행동 + 노랑 형광펜 + Slate 코드 면 | 다크 퍼스트 개발툴(흔하고 문서 장시간 읽기에 불리), 보라·네온 AI 톤(명세가 금지) |
| 중립 | Charcoal 에서 뽑은 따뜻한 회색(`charcoal` 곡선) | Slate 중립 + Blue = Tailwind 기본 SaaS 와 구분 불가 |
| 코드 면 | 두 테마 모두 Slate 어두운 면 | 라이트 코드 면이면 Tangerine·Yellow 가 글자로 쓰일 곳이 없다(흰 면 대비 1.98·1.28) |
| 경고 | Tangerine 면 | 노랑 경고는 '형광펜=강조' 와 충돌. 앰버를 더하면 따뜻한 색이 넷(빨강·탱저린·앰버·노랑)이 된다 |
| 위험 | crimson red(h≈15) 보강 | 탱저린과 h 30° 가까이 떨어뜨려 경고와 위험이 섞이지 않게 |
| 다크 | Charcoal 계열 따뜻한 어둠, Blue·Yellow 값 유지 | Slate 다크(렌더 비교에서 흔한 blue-black 으로 보였다) |
| 버튼 | variant 4개, 기본값 secondary | notting 6개보다 줄였다. 'AI 버튼' 같은 특수 변형 없음 |
| 콜아웃 | GFM alert 5종 이름 그대로 | 자체 이름(Info·Danger)을 만들면 Markdown 과 화면이 두 어휘가 된다 |
| 그라데이션 | 토큰 자체를 없앰 | 허용하면 흔한 AI SaaS 로 가장 먼저 무너진다 |
| 컴포넌트 | CSS + 바닐라 JS 구현까지, 빌드가 lint | 규격만 두면 '하드코딩 금지' 를 기계로 보증할 수 없다 |
| 다이어그램 | 색=개념, 모양=종류, 선=흐름. Mermaid classDef 생성 | 다이어그램마다 색을 고르면 같은 개념이 그림마다 달라진다 |
| 로고 | Blue 타일 + 제도용 Λ 다각형 + 노란 형광펜 가로획, 도형 워드마크 | 둥근 획 Λ(렌더해 보니 아동용 글자처럼 보였다), `</>`·`{}` 류(흔하다) |

## 2. 명세의 질문에 대한 답

| 질문 | 답과 근거 |
|---|---|
| AIP 답게 보이는가? | 형광펜(선언)·탱저린 경계(권한)·Blue(Runtime)가 로고·다이어그램·코드 면·콜아웃에서 같은 의미로 반복된다. 색이 AIP 의 세 약속을 말한다(17 §1) |
| 일반 SaaS 처럼 보이지 않는가? | 따뜻한 Charcoal 중립, 모노 eyebrow·경로형 브레드크럼·절 번호 같은 명세서 표식, 대시보드형 카드 그리드·통계 타일·그라데이션이 없다 |
| 흔한 AI 제품처럼 보이지 않는가? | 보라·네온·글로우·유리·스파클 아이콘이 없다. 'AI' 를 색으로 표시하지 않는다(AIP 는 AI 도구가 아니라 AI 가 쓰기 좋은 프로토콜) |
| 개발자 도구로 충분히 전문적인가? | 리거처 없는 모노, 복사가 프롬프트를 빼는 코드 블록, 언어 동기화 탭, Spec·Params·Signature, ⌘K 검색, 구문 강조 대비 4.5 검사 |
| 문서를 오래 읽어도 편한가? | 16/1.7 본문, 720 열, 흰 종이 + 11.25:1 Charcoal(순검정보다 덜 진동), 문단 20·그림 24 리듬, 장식 모션 없음 |
| Brand Color 가 의미 있게 쓰이는가? | 5색 모두 역할이 하나씩: Blue 행동·AIP, Tangerine 경계·경고, Yellow 강조·선언, Charcoal 글자, Slate 코드·데이터. 장식(accent)은 따로 격리 |
| 기본값이 명확한가? | 클래스 하나 = 가장 흔한 경우. 00 결정표, 16 상황 사전이 '이럴 땐 이것' 하나만 준다 |
| 지나치게 복잡하지 않은가? | variant 4, 콜아웃 5, 성숙도 4, 다이어그램 개념 9, radius 7, 글자 하한 12. 늘리기 전 14 §2 의 '왜 필요한지 한 줄' |

## 3. 렌더 검토에서 고친 것

| 발견 | 고침 |
|---|---|
| 다크 primary 버튼을 blue.500 으로 두면 흰 글자 3.47:1 | 두 테마 모두 AIP Blue, hover 는 어두운 쪽 |
| Warning(tangerine.50)과 Caution(red.50) 배경이 거의 같다 | warning 면을 tangerine.100 으로 |
| 둥근 획 로고가 장난감 글자처럼 보인다 | 수평 발·평평한 꼭대기의 다각형 Λ, 워드마크도 도형 |
| 워드마크 A–I 간격이 넓어 보인다(사선 때문) | I 를 4 당김 |
| `.aip-hide-below-md` 가 같은 명시도 컴포넌트에 져서 모바일 헤더가 25px 넘침 | 유틸을 마지막 파일(utilities.css)로 |
| sticky 사이드바의 면·선이 내용 높이에서 끊긴다 | 셸 배경으로 그림 |
| 파라미터 이름에 본문 인라인 코드 칩이 씌워짐 | prose 인라인 코드는 클래스 없는 `code` 만 |
| 줄 단위 코드(`aip-code__line`)에 빈 줄이 하나씩 더 생김 | block → inline-block(실제 개행이 줄바꿈 담당) |
| 로딩 버튼이 disabled 회색으로 보임 | busy 는 disabled 모양에서 제외 |
| 세그먼트가 세로 스택 안에서 전폭으로 늘어남 | `align-self: flex-start` |
| 그리드 안 두 필드의 높이가 어긋남(형제 margin) | 그리드·스택 자식이면 필드 간격을 끔 |
| fieldset legend 가 섹션 선 위에 걸침 | legend float + 섹션 선을 inset 그림자로 |
| 구문 강조가 prose.css 에만 있어 홈 히어로 코드가 단색 | 같은 매핑을 components.css 에도 생성 |
| 다크 콜아웃 면(blue.950·green.950)이 따뜻한 캔버스 위에서 진한 남색·녹색으로 뜬다 | `dark-tint.*`: 600 을 캔버스에 14% 섞은 생성값 |
| 검색 인풋(type=search)에서 Esc 가 글자만 지우고 닫히지 않는다(Chrome 검사로 발견) | Esc 한 번에 닫기 |
| 컴포넌트 lint 가 `@media` 줄의 규칙을 건너뜀 | 조건 뒤 본문까지 검사 + 색 이름 직접값 검사 |

## 4. 아직 사람이 판단할 것

- AIP 정의 문법이 정해지면 예제 코드 문구 교체(컴포넌트 영향 없음).
- 라이선스 결정 후 `package.json` license·푸터 문구.
- 실제 검색 엔진·Markdown 렌더러 선택(계약은 07 §3·§15 에 있다).
