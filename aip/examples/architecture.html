정의가 실행 가능한 형태가 되기까지.

컴파일 경계

이름, 타입, 정적 규칙을 검사하고 언어 독립 표현으로 옮깁니다.

실행 경계

실행 주체, 정책, 계약을 기준으로 작업을 허용하거나 거부합니다.

02

허용과 거부를
같은 화면에서.

성공하는 경로만 보여주면 정책의 역할을 설명할 수 없습니다. 경계에서 멈추는 이유도 보여줍니다.

호출자는 요청하고,
서버는 판단합니다.

누가 실행하는지 바뀌면 같은 의도의 결과도 달라집니다. 권한 판단은 이미지 속 자물쇠가 아니라 서버의 정책으로 설명합니다.

03

왜 이 구조인가?

기능 설명에서 한 걸음 더 들어가, 선택한 이유와 그 대가를 함께 보여줍니다.

  1. 언어 독립 표현

    작성 형식과 실행 의미의 연결점을 명시합니다.

    얻는 것
    여러 작성 형식이 공통 의미 표현을 공유할 수 있습니다.
    대가
    표현의 호환성과 버전 관리가 별도 책임이 됩니다.

  2. 생성 계약

    클라이언트와 서버 사이에 검증할 수 있는 계약을 둡니다.

    얻는 것
    호출과 결과를 같은 계약에 맞춰 검사합니다.
    대가
    정의 변경과 SDK 재생성의 흐름을 관리해야 합니다.

04

적용 범위도
구조의 일부입니다.

가능한 것을 설명할 때, 아직 결정하지 않은 부분과 외부 운영 책임을 같이 배치합니다.

채택 버전에서 확인

최종 작성 문법, SDK 계약, 쓰기 조합은 정본 문서와 결정 상태를 확인합니다.

이 템플릿은 제품 지원 범위를 보증하지 않습니다.

운영 환경에서 확인

IdP, TLS 배포, 데이터 규모, 무중단 변경은 운영 환경별로 검증합니다.

게시할 때 대상 환경과 결과 자료를 연결하세요.

선택의 배경까지 읽기.

문제, 설계, 실험, 한계를 한 편의 케이스 스터디로 묶습니다.
