01

같은 규칙을 몇 번 쓰고 있나요?

프로젝트의 출발점은 기능의 개수보다, 한 기능을 완성하기 위해 반복하는 경계입니다.

화면 하나가 늘 때마다,
계약과 검증도 다시 만들고 있다면.

문제 제기 예시 · 수치로 입증된 효과를 뜻하지 않습니다.

Controller, DTO, validation, 권한, 트랜잭션, 오류 처리. 같은 의도를 여러 층에 옮겨 쓰면 수정할 지점도 늘어납니다. AIP가 다루려는 것은 이 반복입니다.

02

구현의 책임이 이동합니다.

무엇을 선언하고 무엇을 서버에 남기는지, 같은 기능을 기준으로 나란히 보여줍니다.

기존 방식 · 개념 비교

기능마다 경로를 구현

  • 화면 요구를 요청·응답 계약으로 옮긴다.
  • 권한과 검증을 구현 경로에 연결한다.
  • API 문서와 클라이언트 타입을 맞춘다.

AIP 방향 · 개념 비교

공통 실행 경로로 연결

  • 데이터와 동작에 대한 의도를 정의한다.
  • 정책과 계약을 서버가 검사한다.
  • 생성 계약과 SDK로 호출 경계를 맞춘다.

개념 비교입니다. 코드량 감소나 성능 향상은 별도 측정이 필요합니다.

03

선언은 가볍게.
실행은 엄격하게.

이미지는 개념을 기억하게 하고, 흐름과 텍스트는 정확한 책임을 설명합니다.

04

주장 옆에,
확인할 수 있는 근거.

실행 결과와 성능 비교를 구분하고, 검증된 범위를 함께 공개합니다.

검증 자료

실행 경로와 재현 절차

실제 명령, 환경, 결과 파일을 이 자리에 연결하세요.
