# 07 · 상태와 피드백 — 로딩 · 빈 상태 · 오류 · 확인 · 문구 (notting)

화면은 데이터가 있을 때만 그려지는 게 아니다. 아래 상태를 **전부** 설계해야 화면이 완성된다. notting 은 base 의 9종에 **오프라인 편집·충돌·근거 부족·부분 손실** 이 더해진다.

| 상태 | 언제 | 무엇을 보여주나 |
|---|---|---|
| 초기 로딩 | 첫 진입 | 스켈레톤(제목 1줄 + 블록 6줄, 트리 8항목) |
| 재조회 | 필터·검색어 변경, 재인덱싱 | 기존 내용 유지 + 툴바 아래 2px progress |
| 빈 상태 | 데이터 0건 | §2 |
| 부분 성공 | 40개 중 3개 손실 | 왕복 보고서 모달 + 손실 그룹 펼침 |
| 오류 | 요청 실패 | §3 |
| 오프라인 | 네트워크 없음 | 저장 상태 `offline` + 툴바 아래 neutral 배너. **편집은 계속된다** |
| 충돌 | 서버 revision ≠ 내 base revision | 저장 상태 `conflict` + 배너 "다른 곳에서 수정됨 · 비교" |
| 근거 부족 | Ask 결과에 인용할 chunk 없음 | 중립 면 답변 카드 "근거를 찾지 못했어요" (06 §26) |
| 근거 오래됨 | 인용 문서가 그 뒤 수정·삭제 | 근거 칩 `stale` + 툴팁 |
| 읽기 전용 | 권한 없음·과거 revision | 툴바 배너 + 핸들 없음 |
| 권한 없음 | 403 | 빈 상태 형태, "접근 권한이 없어요" + 요청 |
| 없음 | 404 | 빈 상태 형태, "페이지를 찾을 수 없어요 · 휴지통 확인" + 홈으로 |
| 성공 | 저장·가져오기·삭제 완료 | 토스트 한 문장 |

## 1. 로딩

- **300ms 규칙**: 300ms 안에 끝나면 아무것도 보이지 않는다. "저장 중" 스피너도 300ms 뒤에만.
- 첫 로딩은 스켈레톤, 재조회는 기존 화면 유지.
- 버튼 클릭 후 대기: 그 버튼만 loading. 화면 전체 스피너 금지.
- **AI 응답**: 요청 직후 답변 카드가 즉시 생기고(헤더 + 커서), 첫 토큰까지 스피너 대신 커서만 깜빡인다. 3초 넘게 첫 토큰이 없으면 헤더에 "검색 중…" caption. 10초 넘으면 "시간이 걸리고 있어요" + 중지.
- **가져오기**: progress bar 8 + "12 / 40 파일". 파일 단위로 진행률을 안다.
- **인덱싱**: 툴바 아래 2px 무한 progress + 저장 상태 옆 caption "검색 인덱스 갱신 중". Ask 는 그동안 "최신 변경이 아직 검색에 반영되지 않았을 수 있어요" 배너.
- 낙관적 업데이트(체크박스·상태 변경·정렬)는 즉시 반영, 실패하면 되돌리고 토스트.

## 2. 빈 상태

구성(가운데 정렬, 최대 폭 360):
1. 아이콘 `size.icon.2xl`(48) `text.tertiary`, 또는 배경 원 80 `surface.brand-subtle` + 아이콘 32 `text.brand`
2. 제목 `heading-4` `text.primary` (아이콘 아래 `space.4`)
3. 설명 `body-sm` `text.secondary` 1~2문장 (제목 아래 `space.2`)
4. 주 액션 `primary md` 1개 (설명 아래 `space.6`), 보조는 링크

| 종류 | 제목 | 설명 | 액션 |
|---|---|---|---|
| 워크스페이스 처음 | "첫 페이지를 만들어 볼까요" | "Markdown 폴더가 있다면 그대로 가져올 수도 있어요" | "새 페이지" primary + "Markdown 가져오기" secondary |
| 빈 페이지 | (빈 상태 UI 없음) | 첫 블록 placeholder "명령은 '/', 텍스트는 그냥 입력" | |
| 트리 비어 있음 | "페이지가 없어요" | | "+ 새 페이지" ghost sm |
| 검색 0건 | "'{검색어}' 결과가 없어요" | "다른 단어로 검색하거나 물어보세요" | "필터 지우기" secondary + "워크스페이스에 물어보기" ai |
| Ask 근거 부족 | "근거를 찾지 못했어요" | "이런 검색어는 어떨까요: …" | "일반 지식으로 답하기" secondary |
| 백링크 0 | "이 페이지를 참조하는 문서가 없어요" | | 없음 |
| revision 1개 | "첫 버전이에요" | "수정하면 여기에 기록돼요" | 없음 |
| 이슈 0(처음) | "이슈가 아직 없어요" | "문서에서 할 일을 뽑아 이슈로 만들 수 있어요" | "첫 이슈 만들기" |
| 보드 컬럼 비어 있음 | "이슈를 여기로 끌어오세요" caption | | |
| 필터 결과 0 | "조건에 맞는 이슈가 없어요" | | "필터 초기화" |
| Context Pack 항목 0 | "연결된 문서가 없어요" | "이슈에 문서를 링크하거나 관련 문서를 제안받아 보세요" | "관련 문서 제안" ai |
| 휴지통 비어 있음 | "휴지통이 비어 있어요" | "삭제한 페이지는 30일 동안 여기 남아요" | 없음 |
| 권한 없음 | "볼 수 있는 권한이 없어요" | "워크스페이스 관리자에게 요청하세요" | "권한 요청" |
| 완료(할 일 0) | "모두 처리했어요" | | "보관함 보기" ghost |

- 표·리스트 안 빈 상태는 컨테이너 안 높이 최소 240.
- 일러스트는 `accent.verdigris` `accent.periwinkle` `teal.100` 3색 이내. 없으면 아이콘으로 충분.

## 3. 오류

| 수준 | 표시 | 예 |
|---|---|---|
| 필드 | 인풋 `border.danger` + 아래 `caption` `text.danger` + 아이콘 12 | "페이지 제목은 비울 수 없어요" |
| 폼 | 상단 danger 배너 + 필드 오류, 첫 오류로 포커스 | "2개 항목을 확인해 주세요" |
| 동작 | 토스트(8초) + "다시 시도" | "내보내지 못했어요 · 다시 시도" |
| 저장 | 저장 상태 `error` "저장 실패 · 다시 시도" (클릭). 편집 내용은 로컬에 유지. 3회 실패 시 배너 + "복사해 두기" | |
| AI | 답변 카드 안 danger 인라인 "답변을 만들지 못했어요 · 다시 시도". 검색은 됐는데 생성만 실패면 근거 목록은 보여준다 | |
| 가져오기 | 파일 단위: 보고서에 `dropped` 행. 전체 실패: 모달 안 danger 배너 + "로그 복사" | "3개 파일을 읽지 못했어요" |
| 섹션 | 그 섹션만(패널 탭 하나·보드 컬럼 하나) 오류 + 다시 시도 | 백링크 로딩 실패 |
| 페이지 | 빈 상태 형태 + 오류 ID `mono-label` + "다시 시도" / "홈으로" | 500 |

문구 규칙
- **무엇이 안 됐고 → 왜 → 어떻게** 순서. "오류가 발생했습니다" 금지.
- 사용자 탓하지 않는다.
- 기술 정보(오류 ID·revision 해시)는 `mono-label` `text.tertiary` 로 작게 뒤에.
- **손실은 숫자로 말한다**: "일부 손실" ❌ → "3개 블록이 대체 표현으로 나갑니다" ✅.

## 4. 확인 다이얼로그

언제: **되돌릴 수 없는 것**만 — 영구 삭제, 워크스페이스 삭제, 손실을 감수하는 내보내기, 다른 revision 으로 덮어쓰기.
되돌릴 수 있는 것(휴지통 이동·상태 변경·블록 삭제)은 바로 실행 + 토스트 "되돌리기".

| 요소 | 규격 |
|---|---|
| 폭 | `modal.width-sm` 400 |
| 제목 | `heading-2`, 질문형, 대상 명시: "'아키텍처' 를 영구 삭제할까요?" |
| 본문 | `body-sm` `text.secondary`, 결과 한 문장 + **숫자**: "하위 페이지 4개와 revision 27개가 함께 지워져요." |
| 버튼 | 취소(secondary) · 동작(primary 또는 danger). 동작 이름 그대로 |
| 손실 감수 내보내기 | 제목 "3개 블록은 대체 표현으로 나가요", 본문 "callout 2 · toggle 1 → 인용·들여쓰기", 버튼 "보고서 보기" secondary · "그래도 내보내기" **primary**(파괴가 아니다) |
| 매우 위험 | 워크스페이스 이름 입력해야 버튼 활성 |
| 포커스 | 파괴 동작이면 취소에 첫 포커스 |

## 5. 성공 피드백

| 행동 | 피드백 |
|---|---|
| 자동 저장 | 저장 상태 "저장됨". 토스트 없음 |
| 페이지 만들기 | 새 페이지로 이동, 제목에 포커스. 토스트 없음(화면이 곧 피드백) |
| 가져오기(손실 0) | 토스트 "40개 문서를 가져왔어요 · 손실 없음" 4초 |
| 가져오기(손실 있음) | 보고서 모달(토스트 대신) |
| 내보내기 | 토스트 "내보냈어요 · 보고서 보기" + 다운로드 시작 |
| 삭제(휴지통) | 토스트 "'{제목}' 을 휴지통으로 옮겼어요 · 되돌리기" 8초 |
| 영구 삭제 | 토스트 "영구 삭제됨" 4초, 되돌리기 없음 |
| 복사(Markdown·링크·Context Pack) | 버튼 아이콘 check 1.5초 + 툴팁 "복사됨" |
| 근거 클릭 | 이동 + flash. 토스트 없음 |
| 관계 제안 연결 | 항목이 확정 목록으로 이동. 토스트 없음 |
| 상태 변경(이슈) | 즉시 반영. 토스트 없음 |
| 충돌 해결 | 토스트 "병합했어요 · revision d4e5f6" |

## 6. 비활성(disabled) vs 숨김

- 조건이 곧 충족될 수 있으면 비활성 + 이유: "항목을 선택하면 Context Pack 을 만들 수 있어요".
- 권한이 없어 영원히 못 쓰면 숨김.
- **인덱싱 중 Ask**: 비활성이 아니라 사용 가능 + 배너(오래된 인덱스로라도 답한다).
- 비활성 버튼 툴팁은 감싸는 요소에.

## 7. UX 문구 기본

- 어미는 `-해요` 체. 한 화면에 섞지 않는다. 오류 ID 같은 기술 문구는 명사형.
- 버튼은 동사: "저장" "가져오기" "내보내기" "물어보기" "만들기" "연결" "복원". "OK" "확인" 금지.
- AI 관련 동사는 **AI 가 하는 것처럼 쓰지 않는다**: "AI 가 답변합니다" ❌ → "워크스페이스에 물어보기" ✅. 주어는 사용자다.
- 라벨은 명사, 짧게. 플레이스홀더는 예시.
- 숫자: 천 단위 쉼표, 단위 붙여쓰기, 날짜 `2026.09.20`, 시간 `14:30`, 상대 시간 7일까지. revision 해시는 앞 6자리.
- 손실·충돌·근거 관련 문구는 **항상 개수와 위치**를 넣는다: "callout 2개(adr/0001.md:42, :88)".
- 말줄임: 제목 1줄, 스니펫 2줄, 경로는 앞을 자른다(02 §7).
