# 17 · 경험 템플릿 — 온보딩·인증·빈 상태·복구 (notting)

컴포넌트를 조합하는 법까지 매번 새로 결정하지 않도록 **화면 골격 + 상태 + 다음 행동**을 한 벌로 제공한다. 실제 렌더와 상호작용은 [`examples/experience-templates.html`](../examples/experience-templates.html)에서 확인한다.

## 1. 포함 범위

| 묶음 | 화면 | 1차 과업 |
|---|---|---|
| 온보딩 | 환영 → 워크스페이스 → Markdown 가져오기 → 준비 완료 | 첫 페이지 열기 |
| 접근 | 로그인 · 초대 수락 | 원래 작업 공간으로 진입 |
| 빈 상태 | 첫 워크스페이스 · 검색 0건 · Ask 근거 부족 · 이슈 0건 | 유효한 첫 행동 |
| 복구 | 오프라인 · 읽기 전용 · 충돌 · 403 · 404 · 500 | 잃는 것 없이 복귀 |
| 왕복 | 가져오기 기본 · 진행 · 부분 성공 보고서 | 손실을 확인하고 계속 |

가격·결제·관리자 전용 화면은 제품 정책이 정해지기 전까지 이 시스템에 넣지 않는다. 정책이 없는 화면을 미리 디자인하면 가짜 범용 컴포넌트만 늘어난다.

## 2. 조립 단위

| 패턴 | 책임 | 필수 상태 |
|---|---|---|
| `SetupShell` | 브랜드 면·진행 영역·하단 액션을 묶는 온보딩 셸 | 데스크톱 2열, 모바일 단일 열 |
| `StepIndicator` | 현재 단계·전체 단계·진행률 | 현재 단계가 글자와 막대로 모두 읽힘 |
| `EmptyState` | 빈 이유·설명·주/보조 행동 | 최초 데이터 없음과 검색 0건을 구분 |
| `Coachmark` | 새 기능을 최초 1회만 안내 | 닫기 가능, 다시 열 경로 제공 |
| `SetupChecklist` | 첫 사용자가 남은 설정을 확인 | 완료·다음 항목을 색 외의 형태로 구분 |
| `ResultState` | 성공·부분 성공·실패의 결과와 다음 행동 | 처리 개수·보존 여부·복구 행동 |

## 3. 온보딩 규칙

1. 제품 소개 슬라이드가 아니라 실제 워크스페이스를 만든다.
2. 한 화면에 질문은 하나만 둔다. 주 버튼도 하나만 둔다.
3. 가져오기는 건너뛸 수 있지만 손실 보고서는 생략할 수 없다.
4. 마지막 CTA는 모호한 “완료”가 아니라 `첫 페이지 열기`다.
5. 기능 소개는 편집기 진입 뒤 맥락이 생겼을 때 `Coachmark`로 한 번만 보여준다.

## 4. 빈 상태와 오류 규칙

- `EmptyState`는 **왜 비었는지 → 무엇을 할 수 있는지** 순서로 쓴다.
- 빈 문서에는 큰 일러스트를 두지 않는다. 제목과 첫 블록 placeholder가 편집 시작점이다.
- Ask 근거 부족은 중립 면을 쓴다. periwinkle AI 면에 담지 않는다.
- 오류는 `무엇이 안 됐는지 → 보존된 것 → 다음 행동` 순서다.
- 403은 권한 요청, 404는 홈·휴지통, 500은 재시도와 오류 ID를 제공한다.
- 오프라인·충돌·읽기 전용은 페이지를 덮지 않고 현재 작업 위에 상태 배너로 표시한다.

## 5. 캐릭터 사용

기록지기는 환영, 첫 워크스페이스, 404처럼 감정적 완충이 필요한 대표 장면에만 쓴다. 폼 오류·충돌·손실 보고서에는 쓰지 않는다. 심각한 상태를 캐릭터가 가볍게 보이게 만들 수 있기 때문이다.

| 장면 | 크기 | 허용 |
|---|---|---|
| 온보딩 브랜드 면 | 240~360 | 허용 |
| 첫 워크스페이스 | 160~240 | 허용 |
| 404 | 80~160 | 허용 |
| 로그인·403·500·충돌·손실 | — | 사용하지 않음 |

## 6. 반응형·접근성

- 1024px 아래에서 온보딩은 단일 열로 바뀌고, 768px 아래에서는 브랜드 면을 감춘다. 사용자의 과업을 먼저 남긴다.
- 모든 클릭 대상은 최소 `size.touch-target-min`, 모든 버튼은 실제 `<button>`을 쓴다.
- 상태를 색만으로 말하지 않는다. 아이콘·제목·문구를 함께 쓴다.
- 진행률은 숫자(`2 / 4`)와 막대를 함께 제공한다.
- 모션은 진행 표시와 직접 조작 피드백에만 쓰며 `prefers-reduced-motion`에서 멈춘다.
- 한국어 입력을 제출하는 구현은 `isComposing`을 검사한다. 이 정적 예제는 데이터 제출을 수행하지 않는다.

## 7. 가져다 쓰는 순서

1. `experience-templates.html`에서 필요한 `data-template` 섹션의 마크업을 복사한다.
2. `experience-templates.css`에서 같은 블록의 클래스만 가져온다.
3. 화면 코드는 `--nt-*` 시맨틱 토큰을 유지한다. 원시 색이나 hex로 치환하지 않는다.
4. 정상 화면만 옮기지 말고 같은 묶음의 로딩·빈·오류·오프라인·충돌·읽기 전용을 함께 연결한다.
5. 실제 제품에서 키보드 순서, 긴 한글, 모바일 폭, 라이트·다크를 다시 확인한다.
