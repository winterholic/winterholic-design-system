# 03 · 간격·레이아웃 (Ttakkari)

## 1. 4px 그리드

`space`: 0 · px(1) · 0-5(2) · 1(4) · 1-5(6) · 2(8) · 3(12) · 4(16) · 5(20) · 6(24) · 8(32) · 10(40) · 12(48) · 16(64) · 20(80) · 24(96).
이름은 4px 배수다(`space.4` = 16px). 13·18·25px 이 나오면 잘못 잡은 것이다.

| 관계 | 간격 |
|---|---|
| 같은 요소 안(아이콘↔라벨, 라벨↔인풋) | 8 |
| 같은 사람의 연속 메시지 | 8 |
| 같은 그룹(버튼↔버튼, 칩↔칩 8) | 12 |
| 에이전트 본문 안 블록(문단↔실행 카드↔결과물) | 12 |
| 폼 필드 사이 | 모달 16 · 페이지 20 (필드 묶음은 `.tk-stack`, margin 으로 만들지 않는다) |
| 말하는 사람이 바뀔 때 | 24 |
| 화면 섹션 안 큰 덩어리 | 24~48 |

가까운 것은 가깝게. 한 사람의 말은 붙어 있고, 사람이 바뀌면 숨이 쉬어진다.

## 3. 브레이크포인트와 앱 셸

min-width, 모바일 퍼스트. sm 640 · md 768 · **lg 1024** · xl 1280 · 2xl 1536. 셸이 바뀌는 곳은 lg 하나다.

| 폭 | 셸 | 영역 이동 | 결과물 열기 | 헤더 |
|---|---|---|---|---|
| < 1024 | `[헤더] / [화면(스크롤)] / [컴포저] / [탭바]` | 하단 탭바 4칸 | 전체 화면 뷰어(`dialog.tk-viewer-dialog`) | 56. 앞: 메뉴(세션 드로어) 또는 뒤로 |
| 1024~1279 | `[사이드바 280 | 화면]` | 사이드바 위쪽 `.tk-nav` | 화면 안 분할(`.tk-split[data-open]`), 결과물을 열었을 때만 | 56. 메뉴 버튼 숨김 |
| ≥ 1280 | 위와 같음 | 같음 | 분할을 기본으로 열어 둘 수 있음(`data-open="auto"`) | 같음 |

- 채팅 열은 760 이 상한이다. 분할을 열면 채팅 열은 남은 폭(최소 360), 작업 공간 열은 560 에서 시작해 손잡이로 바꾼다. 둘 다 360 아래로 줄지 않는다(그 폭이면 분할을 닫는다).
- 탭바와 사이드바가 동시에 보이는 폭은 없다(검사 스크립트가 확인한다).

## 5. 모바일 안전 영역·키보드

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` 가 있어야 `env(safe-area-inset-*)` 가 값을 갖는다(예제 테스트가 확인한다).
- 이미 처리한 곳: 헤더 위(노치), 탭바 아래(홈 바), 컴포저 트레이(탭바가 없을 때), 시트·드로어·전체 화면 뷰어, skip link.
- 기본 셸 높이는 `100dvh` 로 주소창 변화에 대응한다. **키보드가 올라왔을 때 컴포저가 보인다는 보장은 아니다.** 키보드가 Visual Viewport 만 줄이면 viewport 단위와 Layout Viewport 는 그대로일 수 있다. 입력 캐럿·컴포저가 실제로 보이는지 확인하고, 필요할 때 `visualViewport` 를 이용한 처리를 적용한다(19 §6). `interactive-widget=resizes-content` 도 모든 브라우저의 보장으로 취급하지 않는다.
- 근거: [CSS Values §6.1.2](https://www.w3.org/TR/css-values-4/#viewport-relative-lengths) · [Chrome viewport resize 동작](https://developer.chrome.com/blog/viewport-resize-behavior). 주소창 대응과 키보드 대응을 따로 검증한다.
- 스크롤은 화면 본문 안에서만 일어난다(`.tk-screen__body`·`.tk-thread`·`.tk-viewer__body`). 페이지 전체가 스크롤되면 헤더·탭바가 같이 밀린다.

### 데스크톱 셸 높이 확인

전체 창을 쓰는 앱은 `.tk-app` 의 위·아래 좌표와 `innerHeight`, 문서의 `clientHeight`, `visualViewport.height/offsetTop` 을 함께 기록한다. 창의 높이를 줄였다가 늘린 뒤에도 셸이 창 아래까지 이어지고, 본문 안에서만 스크롤되는지 본다. 가로 넘침 0 만으로 세로 높이가 맞는 것은 아니다.

소비 앱이 데스크톱에서 `height: 100%` 를 선택하면 `html → body → React 루트 → .tk-app` 사이 모든 래퍼의 높이 기준을 명시한다. 높이가 auto 인 부모 밑에 100% 만 넣지 않는다. 이 방식은 전체 창을 소유하는 앱에 한정하며, 문서 안에 삽입한 예제·위젯에 전역 높이를 강제하지 않는다. 기본 DS 의 `100dvh` 를 오류로 단정하거나, 잘못된 높이를 주입한 시뮬레이션을 사용자 환경의 원인 재현이라고 보고하지 않는다(22 §2 F).

## 6. 정렬 규칙

1. 같은 줄의 컨트롤은 같은 높이(`size.control.*`). 헤더 안은 40(md) 아이콘 버튼, 뷰어 툴바 안은 32(sm).
2. 아이콘은 글자 첫 줄 가운데에 맞춘다(실행 단계·정책 판정·콜아웃이 이미 계산한다).
3. 숫자는 오른쪽, 글자는 왼쪽. 가운데 정렬은 빈 상태·미리보기 상태·로그인만.
4. 목록 행: 앞(글리프 40) · 본문(제목 + 메타) · 뒤(상태·행동). 본문이 남는 폭을 다 쓴다.
5. 표·코드·로그·PDF 는 **그 상자만** 가로 스크롤한다. 페이지 전체가 가로로 밀리면 버그다(검사 스크립트가 6폭에서 잰다).

## 7. 하지 말 것

| ❌ | ✅ |
|---|---|
| margin 13px | `space.3`(12) |
| 채팅 열 1000px | 760. 넓은 화면은 분할로 쓴다 |
| 모바일에서 사이드바를 아이콘 레일로 | 탭바 + 세션 드로어 |
| `position: fixed` 탭바 + 본문 padding 땜질 | `.tk-app` 그리드가 자리를 만든다(탭바는 sticky) |
| 모바일에서 결과물을 새 탭으로 | 전체 화면 뷰어(같은 앱 안, 뒤로 가기로 돌아온다) |
| 키보드가 컴포저를 가린다 | `visualViewport` 와 캐럿·컴포저 좌표를 실기기에서 확인(§5). 본문만 스크롤 |

## 8. 모달 안쪽 여백

모달은 한 상자 안에서 header · body · footer 가 각자 padding 을 가져 겹치기 쉽다. 아래 값이 전부이고, 앱은 이 위에 padding·margin 을 더하지 않는다(B9·C13).

| 위치 | 값 | 토큰·규칙 |
|---|---|---|
| 모달 가장자리 ↔ 화면 | 데스크톱 gutter·위아래 32 · 폭 639 이하 12·16 + safe-area | `.tk-dialog` `--tk-_inset-*` |
| 모달 안쪽 padding(header·body·footer 공통) | 24 · 폭 639 이하 20 | `component.dialog.padding(-mobile)` |
| 제목 ↔ 본문 · 본문 ↔ 푸터 | 16 | `component.dialog.gap` (본문 padding-block) |
| 본문 직계 자식 사이 | 12 | `.tk-dialog__body > * + *` |
| 폼 필드 사이 | 16 | `.tk-stack`(기본 gap). 20(`input.field-gap`)은 페이지 폼 |
| 라벨 ↔ 입력 | 8 | `input.label-gap` |
| 입력 ↔ 도움말 | 6 | `input.help-gap`(`.tk-help` 가 알아서 뺀다) |
| 푸터 버튼 사이 | 12 | 폭 639 이하는 버튼이 폭을 나눠 가진다 |
| 확인 질문(입력 없음) | 폭 400 | `size="sm"` |
| 짧은 입력 폼 | 폭 560(기본) · 긴 폼·목록 720 | `size="lg"` |
| 모달 안 빈 상태 | 위아래 8 | 본문 padding 이 이미 있다(`.tk-dialog__body > .tk-empty`) |

- 필드 묶음은 `.tk-stack`, 가로 짝은 `.tk-grid` 또는 `flex-wrap` + `flex-basis`. 같은 간격을 gap 과 margin 으로 두 번 만들지 않는다.
- 모달 높이는 내용이 정한다. 위아래가 24 를 넘게 비어 보이면 안쪽 요소의 padding 을 먼저 본다(`body-air`).
- 중첩 모달(모달 안에서 여는 확인)은 부모의 크기·간격 변수를 물려받지 않는다. 지역 변수는 자기 선택자에서 초기값을 준다(C8).
