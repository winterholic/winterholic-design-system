# 11 · 접근성 (Ttakkari)

선택 사항이 아니다. **빌드·테스트가 막는 것**과 **사람이 확인할 것**을 나눠 적었다.

## 2. 포커스

- 전역 `:focus-visible` = 2px `interactive.focus-ring` + offset 2px. **지우지 않는다.**
- 입력·컴포저는 바깥 링 대신 테두리 + 안쪽 1px(2px 로 보인다). 탭·목록 행·메뉴 항목·코드·뷰어 본문처럼 촘촘한 곳은 링을 안쪽에.
- 모든 화면 첫 요소는 `.tk-skip-link` → `main#main`(`tabindex="-1"`).
- 다이얼로그·시트·드로어·전체 화면 뷰어가 닫히면 연 요소로 포커스가 돌아간다. 모바일에서 뷰어를 닫으면 고른 결과물 행으로.

## 3. 키보드

| 컴포넌트 | 키 |
|---|---|
| Tabs · 결과물 목록(세로 탭) | ←→ 또는 ↑↓ 이동 = 선택, Home·End |
| Segmented · Radio | 화살표(네이티브) |
| Menu | ↓·↑ 열기, ↑↓ Home End, 글자 점프, Enter, Esc(트리거로 복귀), Tab(닫기) |
| Dialog · Sheet · Drawer | Tab 이 안에 갇힘, Esc 닫기(`data-tk-modal="strict"` 제외) |
| Composer | Enter 보내기 · Shift+Enter 줄바꿈 · ⌘/Ctrl+Enter 보내기 · 한글 조합 중 Enter 무시 |
| 분할 손잡이 | ←→ 32px, Shift 96px, Home·End |
| Viewer | ⌘/Ctrl+F 찾기, Enter·Shift+Enter 다음·이전, Esc 닫기, 본문 포커스 후 화살표 스크롤 |
| 로그·코드·표·본문 | `tabindex="0"` 이라 포커스 후 화살표 스크롤 |
| Tooltip | 포커스에 즉시, Esc 로 닫힘 |

## 4. 터치(모바일 퍼스트)

- 터치 대상 최소 44px. 32·24 컨트롤(아이콘 버튼 sm·xs, 칩, 복사)은 `pointer: coarse` 에서 보이지 않는 히트 영역이 커진다.
- 모바일 주 행동(보내기·승인·거부·시트 버튼)은 48(lg).
- **hover 에만 있는 것이 없다.** 메시지 행동은 터치에서 항상 보이고, 툴팁은 터치에서 뜨지 않으므로 툴팁에만 있는 정보가 없어야 한다. hover 색은 `(hover: hover)` 기기에서만 칠한다(터치 후 hover 가 붙어 남는 문제).
- 입력 16px(iOS 확대 방지). 글자 하한 12px. 200% 확대에서 가로 스크롤 없이 읽힌다(표·코드·로그·PDF 상자 제외).

## 5. 색에만 의존하지 않는다

| 상태 | 색 외의 신호 |
|---|---|
| 누가 말했나 | 말풍선(사용자) ↔ 머리 + 아바타(에이전트), 말한 쪽 모서리 |
| 작업 상태 | 배지 단어 + 단계 아이콘 모양(체크·손·엑스·금지·빈 고리) + 실행 중 맥박 |
| 정책 | 단어 + 아이콘(방패·잠금·금지) |
| 파일 계열 | 아이콘 모양 + 확장자 라벨 |
| 로그 레벨 | 레벨 단어 열 |
| 현재 위치(탭바·내비·탭) | 2px 막대 + 글자색 + `aria-current` |
| 오류 입력 | 아이콘 + 문구 + `aria-invalid` |
| 검색 히트 현재 위치 | 테두리 + n/m |
| diff | `+` `−` 기호 |
| 연결 | 점 + 단어("연결됨·다시 연결 중·오프라인") |

## 6. 시맨틱 구조와 라이브 영역

- 랜드마크: `header` · `nav[aria-label]`(영역·세션·경로 이름이 다르다) · `main` · `aside`.
- 제목은 화면당 h1 하나(헤더의 세션·화면 이름), 순서대로.
- 스레드는 `role="log" aria-live="polite"`. 스트리밍 중인 메시지는 `aria-busy="true"` 로 글자마다 읽히지 않게, 끝나면 뗀다. 실행 단계가 바뀔 때마다 읽지 않는다(시끄럽다). 승인이 필요해지면 한 번 알린다.
- 결과·확인 문구는 `role="status"`. 즉시 알려야 하는 실패(재인증 필요)만 `role="alert"`.
- 진행 막대는 `role="progressbar"` + `aria-valuenow` + `aria-label`.
- 승인 카드는 `section[aria-labelledby]`(제목이 질문).

## 7. 모션

`prefers-reduced-motion` 은 05 §4. 자동 재생·깜빡임 없음. 스트리밍 커서도 깜빡이지 않는다.

## 8. 출시 전 사람이 확인할 것

- [ ] iPhone Safari·Android Chrome 에서: 지시 → 실행 확인 → 승인 → 결과물 열기 → 원본 다운로드 → 뷰어에서 후속 지시까지 한 손으로
- [ ] VoiceOver/TalkBack 으로: 새 메시지·승인 요청이 한 번씩 읽히고, 실행 단계가 쉴 새 없이 읽히지 않는다
- [ ] 키보드만으로(데스크톱) 같은 흐름
- [ ] 다크·라이트 각각 승인 카드·로그·뷰어 상태를 눈으로
- [ ] 홈 화면에 설치한 PWA(standalone)에서 노치·홈 바·키보드가 컴포저를 가리지 않는다
- [ ] 강제 색상 모드에서 포커스와 버튼 경계가 보인다

## 9. 알려진 한계

- `prefers-contrast: more` 전용 토큰은 없다(기본 대비가 이미 AA 이상).
- 강제 색상 모드는 브라우저 기본 처리. inset 그림자로 그린 레일·바는 사라지지만 배지 단어·아이콘이 남는다.
- PDF.js 텍스트 레이어의 스크린 리더 품질은 원본 PDF 에 달려 있다. 스캔 PDF 는 OCR 결과가 없으면 읽히지 않는다(에이전트에게 요약을 시키는 길을 상태 패널에 둔다).
