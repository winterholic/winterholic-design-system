# 20 · 설계 결정과 자기 검토 기록 (Ttakkari v1.0.0)

시드 분석 → 방향 → 토큰 → 컴포넌트 → 브랜드 → 템플릿 순서로 결정했고, 단계마다 실제 Chrome 렌더(라이트·다크·390·1280·1440)로 확인했다. 아래는 결정과 근거, 그리고 검토에서 고친 것이다.

## 1. 결정 요약

| 영역 | 결정 | 버린 대안과 이유 |
|---|---|---|
| 시드 | 13색 값 그대로, 시맨틱이 직접 참조 + 별칭 파일 | 시드를 램프에 녹여 근사값으로: 사용자가 준 화면 느낌이 달라진다 |
| 방향 | 종이 위 지시서 · 잉크 위 기계의 답. Blue 사람 · Mint 에이전트 | 다크 퍼스트 터미널 톤(흔하고 문서 읽기에 불리), 민트 네온 'AI' 톤 |
| Mint 의 자리 | 점·아바타·로고·잉크 면 글자, 다크 글자. 라이트 글자는 mint.700 | 민트를 강조 글자로(종이 위 1.35:1) |
| 성공 색 | Mint(에이전트가 해낸 것) | 별도 녹색: 민트와 녹색 둘이 섞여 읽힌다 |
| 끝난 작업 | 중립 면 + 민트 체크. 조용히 | 성공 배너: 지금 움직이는 것과 사람을 기다리는 것이 묻힌다 |
| 승인 | amber, 채팅 안 카드, 결정 뒤에도 남는 기록 | 확인 다이얼로그: 맥락 없이 누르게 된다. 빨강: 아직 막힌 게 아니다 |
| 별도 정책 범위 | plum | 빨강: '차단'과 '특별 취급'이 같은 색이 된다 |
| 중립 | sage(라이트)·graphite(다크) 두 램프 | 하나의 neutral: 시드의 라이트(녹회색)·다크(청회색) 온도가 다르다 |
| 코드·로그 | 두 테마 모두 잉크 면 | 라이트 흰 코드 면: 민트·연민트가 글자로 설 곳이 없다 |
| 토스트 | 두 테마 모두 잉크 면 | inverse(다크에서 밝아짐): 민트 아이콘이 묻힌다 |
| 컨트롤 | 체크 20·스위치 44×24·탭 44·모바일 주 행동 48 | AIP 크기(18·36×20·40): 손가락에 작다 |
| radius | 카드 12·시트 16 | AIP 8·12: 손에 쥐는 앱에서 딱딱하다 |
| 뷰어 | 형식과 무관한 툴바 자리 + 상태 패널 7종 | 형식별 뷰어 화면 |
| HTML | 별도 출처 sandbox iframe + 격리 띠 상시 | 앱 안 렌더 |
| 컴포넌트 | CSS + 바닐라 JS + React 계약 문서 | React 패키지: 소비 앱 구조가 정해지기 전에 만들면 두 번 만든다 |
| 로고 | Ink 타일 + '따' + Mint ㅏ 획 | ㄷ 두 개 + 커서(§3), 영문 T, 로봇·말풍선 아이콘(흔하다) |

## 2. 질문에 대한 답

| 질문 | 답과 근거 |
|---|---|
| 어떤 상황이든 정본 지침만 따르면 문제없는가? | 00 결정표 · 17 상황 사전(A~R) · 템플릿 5종이 답을 하나씩 준다. 빌드가 대비 510쌍·하드코딩·없는 변수·이름 충돌을, 정적 테스트가 예제 클래스·참조·접근성 이름을, Chrome 검사가 6폭 가로 넘침과 키보드·컴포저·분할·뷰어 동작 58개를 막는다 |
| 모바일에서 완결되는가? | 탭바·바텀 시트·전체 화면 뷰어·safe-area·48 주 행동·16 입력. 지시 → 승인 → 결과물 열기 → 원본 다운로드 → 후속 지시가 390 폭 템플릿에서 끝난다 |
| 결과물 마지막 단계까지 완성도가 있는가? | 뷰어 본문 7종 + 상태 7종, 원본/파생 구분, 변환 안내, 보면서 지시, 보관함 상세(ID·해시·보존·정책·기록) |
| 보안 경계가 화면에서 흐려지지 않는가? | 접근과 반출을 다른 배지로, 판정은 서버 결과 그대로, 승인은 카드에서만, HTML 격리 띠 상시(18 §3) |
| 흔한 AI 제품처럼 보이지 않는가? | 민트 글로우·그라데이션·반짝이 아이콘이 없다. 에이전트는 한글 '따' 와 작은 민트 점으로만 드러난다 |

## 3. 렌더 검토에서 고친 것

| 발견 | 고침 |
|---|---|
| 로고 첫 시안(ㄷ ㄷ + 커서)이 라틴 "CC." 로 읽힌다 | ㅏ 를 붙여 '따' 한 음절로. 민트는 ㅏ 의 가로획 |
| ㄷ 사이 간격이 좁아 작은 크기에서 붙는다 | 16 → 20, ㅏ 와의 간격 30 |
| 헤더 제목이 위로 잘린다(메타 `<p>` 의 기본 margin) | 컴포넌트 안 문단 margin 을 base 에서 끈다 |
| 사이드바 그룹 사이가 너무 벌어진다(같은 원인) | 같음 |
| 작업 공간에서 뷰어 9개가 한꺼번에 보인다(`display:flex` 가 `hidden` 을 이김) | `[class*="tk-"][hidden] { display: none }` |
| 스프레드시트 머리 행이 본문과 어긋난다 | 뷰어 표 `.tk-grid` 가 레이아웃 `.tk-grid`(CSS grid)와 이름이 겹쳤다 → `.tk-cells`. 빌드에 **이름 충돌 검사** 추가 |
| 글자 역할 `.tk-code`·`.tk-log`·`.tk-message` 가 컴포넌트와 겹친다 | `source`·`log-line`·`body-message` 로. 같은 검사가 막는다 |
| 선택한 결과물 행이 '새 결과물' 민트 면에 가려진다 | 새 표시는 선택·현재가 아닐 때만 |
| 다크에서 사이드바 로고 타일이 사라진다 | 헤더 브랜드 타일에 외곽선 한 줄, 단독 로고는 타일 없는 inverse 락업 |
| 코드 빈 줄의 줄 번호가 다음 줄과 겹친다 | 줄마다 최소 높이 1lh |
| 모바일 컴포저 단축키 안내가 두 줄로 깨진다 | 좁은 화면·터치에서 숨김 |
| 1024 폭에서 분할이 1px 넘친다(손잡이) | 작업 공간 열 최대 폭에서 손잡이 폭을 뺀다 |
| 다크 토스트에서 민트 아이콘이 안 보인다(inverse 가 밝아짐) | 토스트를 두 테마 모두 잉크 면으로 |
| 대비 미달 12건(첫 빌드): 라이트 live 점 2.99, 승인 레일 2.34, 다크 입력 경계 3.00 등 | live·연결 점 mint.600, 레일은 아이콘 색, 다크 strong graphite.500 |
| 선택 모드 초기화가 빈 선택자로 오류 | 빈 값이면 범위 안에서 찾는다 |
