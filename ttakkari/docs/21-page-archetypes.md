# 21 · 페이지 아키타입 (Ttakkari)

새 화면을 만들 때 **이 문서만 보면 되도록** 앞으로 들어올 페이지 유형을 레이아웃 패턴(아키타입)으로 정리했다. 화면마다 모바일(320·390) → 태블릿(768) → 데스크톱(1024 이상) 배치, 쓸 컴포넌트, 상태, 금지를 적었고, 각 아키타입은 `examples/archetypes/` 에 **실제로 열리는 예제**가 있다(6폭에서 가로 넘침 0, 긴 글자 주입 통과).

## 0. 사용법

1. §1 표에서 만들려는 화면에 가까운 아키타입을 고른다. 둘 사이에 걸치면 "같은 대상의 다른 보기 = 탭", "서로 다른 대상 = 칸"으로 가른다.
2. 해당 예제 HTML 을 복사해서 시작한다. 셸·헤더·탭바는 14 §1 과 같다.
3. §2 의 공통 규칙과 22 §5 체크리스트를 확인한다.
4. 예제에 없는 부품이 필요하면 15 §2 절차로 시스템에 먼저 넣는다(화면을 위해 시스템을 우회하지 않는다).
5. `npm run check:layout`(예제) 또는 앱의 `pnpm check:layout` 으로 6폭·긴 글자 검사를 통과한다.

## 2. 모든 아키타입의 공통 규칙

### 셸과 스크롤
- 셸은 14 §1(`.tk-app` > `.tk-screen`). 한 화면 = 헤더 + 스크롤 본문. 스크롤은 본문 또는 **칸 안**(`tk-panes__scroll`)에서만 일어난다.
- 헤더 제목은 h1, 한 줄 말줄임 + `title`. 메타 줄은 상태 한두 가지. 화면 안 행동은 헤더 오른쪽 아이콘 버튼 둘까지, 더 있으면 더보기 메뉴.
- 가로 모드 폰의 좌우 노치와 아래 홈 바는 셸이 처리한다. 셸 밖 전체 화면 요소는 22 C5·C6 을 따른다.

### 폭 단계
| 폭 | 칸 | 이동 | 모달 |
|---|---|---|---|
| 320·390 | 1 칸(탭으로 전환) | 하단 탭바(영역) + 화면 안 탭(`tk-tablist`) | 짧은 것은 `.tk-dialog`, 문서는 전체 화면 뷰어 |
| 768 | 1 칸(여백이 넓어짐), 표·카드는 2열 | 같음 | `.tk-dialog` |
| 1024 이상 | 컨테이너가 64rem 이상이면 2·3 칸 나란히 | 사이드바 | `.tk-dialog`, 뷰어는 분할 |

3 칸은 **컨테이너 폭**으로 정한다. 사이드바(280)가 폭을 먹으므로 1280 화면은 컨테이너 1000 이라 나란히 3 칸이 된다(시작 280 · 가운데 360 이상 · 끝 360).

### 상태(모든 화면이 갖는다)
| 상태 | 표현 |
|---|---|
| 빈 | `.tk-empty`(+ `.tk-art` 자리 + 제목 + 한 줄 이유 + 행동 하나). 해당 아키타입의 일러스트 키는 23 |
| 로딩 | 실제와 같은 개수·모양의 `.tk-skeleton`. 1초 안쪽은 지연해서 깜빡임을 줄인다. 표는 스켈레톤 행, 차트는 `aria-busy` |
| 오류 | `.tk-callout--caution role="alert"` + 다시 시도. 부분 실패(일부 파일·일부 지표)는 그 자리만 오류로 두고 나머지는 보여 준다 |
| 오프라인 | 앱 띠 `.tk-banner`(10). 마지막으로 받은 값은 남기고 "마지막 갱신 시각"을 적는다 |
| 권한 | 접근과 반출을 다른 배지로(08). 서버 판정 그대로 |

### 대량 데이터
목록·표·diff·로그는 처음 50개만 그리고 "더 보기"(또는 가상 스크롤)로 늘린다. 1,000줄 넘는 diff·로그는 접어서 시작한다. 전체 건수를 먼저 보여 주고 불러온 만큼을 따로 적는다.

### 되돌리기 어려운 행동
병합·발행·삭제·원격 조종 시작·반출은 Approval 카드(08) 또는 `.tk-dialog` 로 한 번 묻는다. 에이전트가 하는 일이면 Run 카드로 보이고, 사람의 허락은 Approval 카드에서만 받는다. 연결 끊기·닫기처럼 되돌릴 수 있는 일은 묻지 않는다.

### 접근성
- 그래프·차트·캔버스는 **목록·표 대안**을 같은 화면 안에 둔다(키보드·스크린 리더·작은 화면).
- 칸 전환 탭은 `role=tablist` 화살표 이동. 포커스를 새 칸 제목으로 옮긴다.
- 토글은 `aria-pressed`, 선택은 `aria-selected`, 진행은 `role=progressbar`. 색만으로 상태를 말하지 않는다.

## 3. A · 저장소 열람 (`archetypes/repo-browser.html`)

GitHub 모바일 앱 대용. 저장소 홈에서 폴더를 따라 내려가 파일을 읽는다.

```
모바일:  [헤더: ← 저장소 / main · 최근 커밋]
         [탭: 파일 | 코드]
         [브랜치 버튼 · 커밋 수]  [경로 breadcrumb]  [폴더·파일 행…]  → 파일을 누르면 '코드' 탭
데스크톱: [사이드바] [파일 280 ┃ 코드(도구줄 + 줄 번호 코드)]
```

- **모바일 320·390**: 탭 둘(파일·코드). 파일 목록 행은 글리프 + 이름(한 줄) + 메타(마지막 커밋 메시지·시각). 경로는 `.tk-path`(767 이하에서 앞쪽을 `…` 로 접는다). 코드는 가로 스크롤, 줄 바꿈 토글.
- **태블릿 768**: 같은 1 칸. 여백이 넓고 코드 도구줄이 한 줄에 다 들어간다.
- **데스크톱 1024+**: 파일(280)과 코드가 나란히. 코드가 남는 폭을 쓴다. 파일 이름이 길어도 목록 폭은 변하지 않는다.
- **컴포넌트**: `tk-panes`(탭 모바일) · `tk-select`(브랜치) · `tk-path` · `tk-list`(행) · `tk-toolbar`(복사·줄 바꿈·원본 다운로드) · `tk-code--viewer`(줄 번호) · README 는 `tk-prose`.
- **상태**: 빈 저장소(`empty-github-project` 일러스트 + "첫 커밋을 올려 보세요") · 로딩(행 스켈레톤 6개) · 오류(권한·속도 제한은 `tk-callout--warning` + 재시도 시각) · **큰 파일/바이너리**는 코드 대신 상태 패널(`tk-viewer__state`) + 원본 다운로드 · 이미지는 이미지 뷰어.
- **금지**: 파일 전체를 DOM 으로 한 번에(2,000줄 초과는 구간 렌더) · 에이전트가 준 경로로 직접 URL 을 만드는 것(Artifact ID 로 연다) · 코드를 흰 종이 면에(코드는 잉크 면) · 파일 이름 말줄임에 `title` 없음.

## 4. B · PR · diff (`archetypes/pull-request.html`)

풀 리퀘스트·이슈 상세. 같은 대상의 세 보기라 칸이 아니라 **탭**이다(`tk-panes--tabs`).

```
모바일:  [헤더: ← #128 제목 / 열림 · head → base]   [탭: 대화 | 커밋 3 | 변경 파일 12]
         대화: 설명 카드 → 검사 결과(tk-checks) → 활동(tk-timeline) → 병합 승인(tk-approval)
         변경 파일: 도구줄(보는 파일 수 · 줄 바꿈) → 파일별 tk-diff(접힘)
데스크톱: 같은 탭 구조, 내용 폭 1120(tk-container--lg)
```

- **모바일 320·390**: diff 는 통합 보기(unified). 줄 번호 두 칸이 가로 스크롤에서 고정, 긴 줄은 "줄 바꿈" 버튼으로 접는다. 파일은 접힌 채 시작(큰 PR 은 처음 2개만 펼침). 병합 승인은 화면 아래가 아니라 대화 끝의 Approval 카드.
- **태블릿 768**: 통합 보기 유지. 폭이 넓어 줄 바꿈 없이 대부분 읽힌다.
- **데스크톱 1024+**: md 이상에서 나란히 보기(`data-view="split"`)를 고를 수 있다. 파일 목록(왼쪽 고정)은 변경 파일이 많을 때(30개 초과) 추가.
- **컴포넌트**: `tk-tablist` · `tk-diff` · `tk-timeline` · `tk-checks` · `tk-approval` · `tk-badge[data-state]`(열림·병합·닫힘은 run 상태 색을 빌려 쓰지 않고 배지 단어로) · `tk-toolbar` · 리뷰 댓글 `tk-diff__thread`.
- **상태**: PR 없음(빈) · 변경 파일 로딩(파일 머리 스켈레톤 + 본문은 펼칠 때 로드) · 오류(파일 단위) · 충돌(`tk-callout--warning` + 해결 안내, 병합 승인 비활성) · 검사 진행(`tk-checks` 의 아이콘 + 단어) · 리뷰 요청됨(타임라인).
- **금지**: 병합·닫기를 에이전트가 사용자 승인 없이(Approval 카드) · diff 색만으로 추가·삭제 표시(기호 칸 필수) · 1,000줄 파일을 펼친 채 시작 · 코드 줄을 `<br>` 로 이어 붙인 한 덩어리.

## 5. C · 자료 노트 (`archetypes/notebook.html`)

NotebookLM류. 자료를 올려 두고 **선택한 자료에서만** 답을 받고, 산출물(요약·FAQ·지도)을 만든다.

```
모바일:  [헤더]   [탭: 자료 | 대화 | 산출물]   (기본 '대화')
데스크톱: [자료 280(체크로 사용 선택) ┃ 대화 + 컴포저 ┃ 산출물 360]
```

- **모바일 320·390**: 탭 셋. 자료 탭은 선택 체크 + 색인 진행. 대화에는 답마다 근거 칩(`[1] 파일 · 12쪽`)이 붙고 누르면 자료 탭의 그 자리로 간다.
- **태블릿 768**: 1 칸. 컴포저가 아래에 고정(탭바 위).
- **데스크톱 1024+**: 3 칸. 자료 선택을 바꾸면 컴포저 힌트 문구("선택한 자료 3개")가 바뀐다.
- **컴포넌트**: `tk-panes`(3칸) · `tk-list` + 체크 · `tk-progress`(색인) · `tk-message`(에이전트 답 + `tk-callout--note` 로 "사용하지 않은 자료") · `tk-chip`(근거) · `tk-composer`(Enter 규칙: 한글 조합 중 전송 안 함, 터치 Enter 는 줄바꿈).
- **상태**: 자료 0개(`empty-notebook-library` + "자료를 추가해 보세요") · 색인 중(진행 + 아직 읽는 중인 자료는 질의에 쓰지 않음을 안내) · 자료 실패(그 행에 오류 배지 + 다시 시도) · 답에 근거가 없음("자료에서 찾지 못했어요", 추측 답 금지) · 오프라인(질문 보내기 비활성 + 이유).
- **금지**: 근거 없는 답을 근거 있는 것처럼 보이게 · 자료 이름을 말줄임만으로(긴 URL·파일명은 `title` + 줄바꿈) · 승인 없이 자료를 외부로 보내기(반출은 파일 찾기와 같은 정책) · 인용 번호를 색만으로.

## 6. D · 연구 지표 (`archetypes/research.html`)

ML·LLM 실험. 지표 타일 → 곡선 → 실행 표 → 비교. 읽는 화면이지 편집 화면이 아니다.

```
모바일:  기간 segmented + 새로고침 / 지표 타일 2×2 / 차트(범례 위·읽기 줄·데이터 표) / 실행 표(첫 열 고정, 가로 스크롤)
데스크톱: 타일 4열 / 차트 + 비교 사이드(선택한 실행)
```

- **모바일 320·390**: 타일은 2열(`tk-stats` 가 자동). 차트는 16:9, 범례는 위에 줄바꿈. 값은 호버 대신 **읽기 줄**(`tk-chart__readout`)과 `details` 데이터 표. 표는 첫 열(실행 이름) 고정 + 가로 스크롤, 선택 체크 열이 맨 앞.
- **태블릿 768**: 타일 4열, 차트 `--wide`. 표는 가로 스크롤이 줄어든다.
- **데스크톱 1024+**: 차트가 크고 비교 선택(체크한 실행 2~4개)이 차트 시리즈가 된다. 시리즈는 6개까지(색 6 + 선 모양).
- **컴포넌트**: `tk-stat`(+ `tk-spark`) · `tk-chart` · `tk-legend` · `tk-datatable`(sticky-col · sort · 체크) · `tk-badge[data-state]`(실행·완료·실패) · `tk-segmented`(기간) · `tk-timeline`(실행 이력).
- **상태**: 실험 없음(`empty-ml-research`) · 지표 로딩(`tk-chart[aria-busy]` + 스켈레톤 행) · 지표 서버 오류(차트 위 `tk-chart__state`, 마지막 값은 남김) · 실행 중(`tk-dot--live` + 자동 갱신 주기를 글로) · 실패 실행(OOM 같은 이유 한 줄).
- **금지**: 좋고 나쁨을 색만으로(▲▼ + 단어) · 시리즈 7개 이상을 한 차트에(비교 선택으로 줄인다) · 값을 호버 툴팁에만 · 표를 카드 N 장으로 바꿔 숫자 열 비교를 못 하게(열이 많으면 가로 스크롤 + 첫 열 고정) · 축 글자 12 미만.

## 7. E · 글쓰기 (`archetypes/editor.html`)

블로그 에디터. 쓰는 동안 화면이 움직이지 않는 것이 전부다.

```
모바일:  [헤더: ← 제목 / 초안 · 저장됨 14:32 · 발행(primary)]  [탭: 글 | 쓰기 | 미리보기]
         쓰기: 도구줄(가로 스크롤) → 본문(읽기 폭) → 상태 줄(저장·글자 수)
데스크톱: [글 목록 280 ┃ 편집 ┃ 미리보기·메타 360]
```

- **모바일 320·390**: 기본 탭은 '쓰기'. 도구줄은 한 줄 가로 스크롤(줄바꿈 금지). 키보드가 올라오면 탭바는 숨고(`html[data-kbd]`) 캐럿은 `visualViewport` 안으로 스크롤된다. 본문 글자 16.
- **태블릿 768**: 편집 1 칸 + 미리보기는 탭. 도구줄이 모두 보인다.
- **데스크톱 1024+**: 3 칸. 편집이 읽기 폭(720)으로 가운데, 미리보기·슬러그·태그는 오른쪽.
- **컴포넌트**: `tk-editor` · `tk-toolbar` · `tk-panes` · `tk-field` · `tk-prose`(미리보기) · `tk-dialog`(발행 확인) · `tk-badge`(초안·발행됨).
- **상태**: 글 없음(`empty-blog` + "첫 글을 써 보세요") · 저장 중/저장됨/저장 실패(글자 + `data-save`, 실패하면 로컬에 남겼다고 알린다) · 오프라인(계속 쓸 수 있고 "연결되면 저장")  · 충돌(다른 기기에서 수정됨: 두 버전 비교 후 선택) · 발행 오류.
- **금지**: 자동 저장 없이 이탈 시 유실 · 화면 회전·크기 변경 때 편집기를 새로 만들어 초안을 날리는 것(열 때 표시 방식을 고정) · 도구줄 줄바꿈 · 입력 글자 16 미만 · 발행을 확인 없이(공개 주소로 바로 올라간다).

## 8. F · 구조 그래프 (`archetypes/graph.html`)

하네스 시각화(스킬·훅·에이전트·도구의 연결). 눈으로 구조를 보고, 목록으로 정확히 읽는다.

```
모바일:  [탭: 그래프 | 목록 | 상세]  필터 칩 줄 / 캔버스(핀치·끌기) + 줌 버튼
데스크톱: [목록 280 ┃ 그래프 ┃ 선택한 노드 360]
```

- **모바일 320·390**: 기본 탭 '그래프'. 한 손가락 끌기 = 이동, 두 손가락 = 확대, "전체 보기" 버튼이 항상 있다. 노드를 누르면 상세 탭으로 간다(또는 시트). 미니맵은 숨긴다.
- **태블릿 768**: 미니맵이 나타난다. 상세는 탭.
- **데스크톱 1024+**: 목록 | 그래프 | 상세 3 칸. 키보드로 노드를 오가고(`Tab`/방향키) 선택이 목록·그래프·상세에서 같이 움직인다.
- **컴포넌트**: `tk-canvas`(+ `tk-canvas__controls`) · `tk-node` · `tk-edge` · `tk-chip`(종류 필터, `aria-pressed`) · `tk-list`(같은 노드의 목록 대안) · `tk-meta`(상세) · `tk-badge[data-state]`.
- **상태**: 노드 없음(`empty-harness-visualization`) · 로딩(노드 자리 스켈레톤 카드, 선은 나중에) · 오류(캔버스 위 안내 + 목록은 계속) · 필터 결과 0건("필터 모두 풀기") · 노드 많음(50 초과 시 종류별 클러스터로 접기).
- **금지**: 그래프만 있고 목록·키보드 경로가 없는 것 · 노드 제목 말줄임에 `title` 없음 · 선을 색만으로 구분(활성은 굵기 + 색) · 페이지 전체가 핀치 확대되는 것(`touch-action: none` 은 캔버스에만) · 노드 안에 긴 본문(제목 + 메타 한 줄까지, 나머지는 상세).

## 9. G · 시장 대시보드 (`archetypes/market.html`)

주식. 숫자가 주인공이고 틀린 숫자는 사고라서, 신선도(몇 분 전 값인가)를 항상 보인다.

```
모바일:  [배너: 장 마감 · 15분 지연] / 지표 타일 2×2(+스파크) / 시세 차트(기간 segmented) / 관심 종목 표(첫 열 고정) / 리포트·공시 목록
데스크톱: 타일 4열 / 차트 | 관심 종목 2열 / 리포트
```

- **모바일 320·390**: 타일 2열, 차트 `--wide`(낮고 넓게), 기간은 segmented(1일·1주·1개월·1년). 종목 표는 가로 스크롤 + 첫 열(종목) 고정, 등락 열은 ▲▼ + 부호 + 색.
- **태블릿 768**: 타일 4열. 표가 대부분 한 화면.
- **데스크톱 1024+**: 차트와 관심 종목이 나란히, 리포트 목록이 아래 전폭.
- **컴포넌트**: `tk-stat` · `tk-spark` · `tk-chart` · `tk-segmented` · `tk-datatable`(sticky-col) · `tk-banner`(장 상태·지연·오프라인) · `tk-list`(리포트·공시, 글리프 pdf/doc) · `tk-stat__delta[data-tone]`.
- **상태**: 관심 종목 없음(`empty-stock-analysis`) · 시세 로딩(마지막 값 유지 + `aria-busy`, 값을 0 으로 비우지 않는다) · 시세 서버 오류(배너 + 마지막으로 받은 시각) · 장 마감·휴장(배너) · 지연 시세(항상 표시).
- **금지**: 상승=초록·하락=빨강 같은 외국 관례를 임의로(국내 관례는 상승 빨강·하락 파랑이고 **페이지가 tone 으로 고른다**, 화살표·부호 필수) · 주문·자동매매 버튼(범위 밖, 요청 전 금지) · 시세 숫자를 tabular 가 아닌 글꼴로 · 원 단위와 퍼센트를 한 칸에 섞기 · 지연·마감 표시 생략.

## 10. H · 창작 작업대 (`archetypes/creative.html`)

게임 제작 도구, Adobe 대체 오픈소스(Krita·GIMP·Inkscape) 작업 화면. 레이어·에셋 | 캔버스 | 속성.

```
모바일:  [탭: 레이어 | 캔버스 | 속성]  캔버스 탭: 도구줄 / 캔버스(끌기·핀치) / 타임라인 줄(재생·위치)
데스크톱: [레이어 280 ┃ 캔버스(도구줄 위, 타임라인 아래) ┃ 속성 360]
```

- **모바일 320·390**: 기본 탭 '캔버스'. 도구는 도구줄(가로 스크롤) 한 줄, 현재 도구 `aria-pressed`. 속성은 탭에서 편집하고 캔버스로 돌아오면 반영. 입력은 16.
- **태블릿 768**: 레이어·속성은 여전히 탭이지만 캔버스가 넓어 정밀 조작이 낫다.
- **데스크톱 1024+**: 3 칸. 마우스 휠 확대, 키보드 이동·확대(`+ - 0`).
- **컴포넌트**: `tk-panes` · `tk-canvas` · `tk-toolbar`(위 도구 / 아래 `--bottom` 타임라인) · `tk-tree`(레이어) · `tk-field` · `tk-select` · `tk-progress`(재생 위치) · `tk-chip`(배율).
- **상태**: 프로젝트 없음(`empty-game-creation`) · 에셋 로딩(스켈레톤 타일) · 저장 실패(로컬 유지 안내) · 도구 실행 오류(작업 로그를 `tk-log` 로, 에이전트가 만든 변경은 Run 카드) · 되돌리기 가능 범위 표시.
- **금지**: 캔버스 밖 페이지 스크롤과 캔버스 제스처 충돌(`touch-action` 은 캔버스에만) · 레이어 이름 말줄임에 `title` 없음 · 파괴적 일괄 삭제를 확인 없이 · 도구 전환을 색만으로 · 속성 입력을 슬라이더로만(숫자 입력 병행).

## 11. I · 원격 조종 (`archetypes/remote.html`)

VPN 동일망의 Mac 화면을 보고 제어. 가장 위험한 화면이라 **연결 상태·승인 상태가 항상 보인다**.

```
모바일:  [배너: VPN 안에서만 · 승인된 기기만] / 연결 알약 + 지연 / 스트림(영상 + HUD + 제어 바) / Keybar(특수 키)
데스크톱: 스트림이 폭을 쓰고(높이는 화면 안), 제어 바는 영상 아래, 로그·클립보드는 오른쪽 칸(선택)
```

- **모바일 320·390**: 영상은 비율대로(contain), 높이는 화면(헤더·탭바 제외)을 넘지 않는다. 제어 바는 아이콘 버튼(키보드·마우스 모드·화질·전체 화면) + `연결 끊기`(danger). 전체 화면 가로 모드에서 좌우 노치·홈 바를 피한다. 마우스 모드는 직접(탭 = 클릭)과 상대(트랙패드 `tk-pad`) 둘.
- **태블릿 768**: 영상이 커지고 제어 바가 한 줄에 다 들어온다.
- **데스크톱 1024+**: 영상 + 오른쪽 칸(세션 로그 `tk-log`, 클립보드). 키보드 입력은 영상에 포커스가 있을 때만 전달하고 Esc 로 빠져나온다.
- **컴포넌트**: `tk-stream` · `tk-keybar` · `tk-pad` · `tk-banner` · `tk-presence` · `tk-approval`(조종 시작) · `tk-button--danger`(끊기) · `tk-spinner` · `tk-log`.
- **상태**: 연결 전(기기 없음 → `empty-remote-control` + "Mac 에서 이 기기를 승인하세요") · 연결 중(스피너 + 단계) · live · degraded(지연 큼: 아래 띠로만 알리고 입력은 유지) · lost(영상 위 막 + 입력 차단 + 다시 연결) · 승인 만료(재인증 Dialog).
- **금지**: VPN 밖에서 연결을 시도하게 두는 것 · 승인 없이 입력 전달 · 연결이 live 가 아닌데 입력을 보내는 것 · 영상 늘리기(비율 깨짐) · 비밀번호 입력 필드를 영상 위에 겹쳐(원격 화면의 입력은 원격에서) · 연결 끊기를 확인창으로 막는 것.

## 12. J · 결과 갤러리·비교 (`archetypes/gallery.html`)

이미지·영상 결과를 모아 보고, 전후를 비교하고, 어떤 도구로 만들었는지 본다.

```
모바일:  검색 + 건수 / 격자 2열(정사각 타일 + 파일명 한 줄) / 비교 카드(전·후·슬라이더) / 만든 도구 칩
데스크톱: 격자 4~6열 + 오른쪽 상세(400)에서 메타·비교
```

- **모바일 320·390**: 격자는 `tk-grid--auto`(타일 최소 폭이 화면에 맞게). 선택 모드는 체크 → 아래 `tk-selectionbar`. 비교는 세로 카드, 전/후 토글(segmented), 슬라이더는 터치 지원.
- **태블릿 768**: 격자 3~4열.
- **데스크톱 1024+**: 타일 클릭 = 오른쪽 상세, 비교는 상세 안에서 좌우 분할.
- **컴포넌트**: `tk-grid--auto` · `tk-filterbar` · `tk-segmented` · `tk-selectionbar` · `tk-chip`(도구) · `tk-card` · `tk-meta` · 영상은 `<video controls>` + 포스터.
- **상태**: 결과 없음(`empty-work-visualization`) · 썸네일 로딩(정사각 스켈레톤, 레이아웃이 튀지 않게 `aspect-ratio`) · 미리보기 불가(상태 패널 + 원본 다운로드) · 큰 파일(다운로드만) · 선택 0건.
- **금지**: 썸네일이 로드되면서 격자가 밀리는 것(비율 고정) · 원본이 아닌 변환본을 "원본"으로 다운로드 · 영상 자동 재생(소리) · 파일명을 한 줄 말줄임만으로(상세에서 전체) · 비교 전/후 레이블 없음.

## 14. 새 아키타입을 늘릴 때

1. 같은 칸 구성·상태·금지를 가진 화면이 **둘 이상** 생길 때만 아키타입으로 올린다. 한 번뿐이면 가장 가까운 아키타입의 변형으로 만든다.
2. 부품이 없으면 15 §2 로 컴포넌트를 먼저 만든다(`components/*.css` → 24 에 마크업 계약 → 예제).
3. 이 문서에 §1 표 한 행 + 절 하나(모바일 320·390 · 태블릿 768 · 데스크톱 1024+ · 컴포넌트 · 상태 · 금지) + `examples/archetypes/<이름>.html`. 정적 테스트가 예제와 이 문서의 짝을 확인한다.
4. 예제가 `check:layout` 위반 0 을 통과해야 한다.

예상되는 다음 후보: 오디오·영상 편집 타임라인(H 의 확장), 번역·문서 비교(B 의 diff 재사용), 일정·예약 보드(칸반 `tk-panes`), 에이전트 실행 모니터(D + `tk-log`).
