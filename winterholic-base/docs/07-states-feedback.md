# 07 · 상태와 피드백 — 로딩 · 빈 상태 · 오류 · 확인 · 문구

화면은 데이터가 있을 때만 그려지는 게 아니다. 아래 상태를 **전부** 설계해야 화면이 완성된다.

| 상태 | 언제 | 무엇을 보여주나 |
|---|---|---|
| 초기 로딩 | 첫 진입, 데이터 없음 | 스켈레톤(레이아웃 자리 유지) |
| 재조회 | 필터 변경·새로고침 | 기존 내용 유지 + 상단 무한 progress 2px, 또는 `opacity.disabled` |
| 빈 상태 | 데이터 0건 | §2 |
| 부분 성공 | 10개 중 3개 실패 | warning 배너 + 실패 항목 표시 |
| 오류 | 요청 실패 | §3 |
| 오프라인 | 네트워크 없음 | 상단 neutral 배너 "오프라인입니다. 연결되면 자동으로 다시 시도합니다" |
| 권한 없음 | 403 | 빈 상태 형태, "접근 권한이 없습니다" + 요청 방법 |
| 없음 | 404 | 빈 상태 형태, 홈으로 |
| 성공 | 저장·삭제 완료 | 토스트 한 문장 |

## 1. 로딩

- **300ms 규칙**: 300ms 안에 끝나면 아무것도 보이지 않는다. 300ms 지나면 스켈레톤·스피너.
- 첫 로딩은 스켈레톤, 이후 재조회는 기존 화면 유지. 데이터가 바뀔 때 화면이 비었다가 채워지면 깜빡인다.
- 버튼 클릭 후 응답 대기: 그 버튼만 loading(스피너 + 폭 유지), 나머지는 그대로. 화면 전체 스피너 금지.
- 10초 넘게 걸리면 "시간이 걸리고 있습니다" 문구 + 취소.
- 낙관적 업데이트(좋아요·토글·정렬)는 즉시 반영하고 실패하면 되돌리며 토스트로 알린다.

## 2. 빈 상태

구성(위에서 아래로, 가운데 정렬, 최대 폭 360):
1. 아이콘 `size.icon.2xl`(48) `text.tertiary` 또는 `brand.mist` 배경 원 80 + 아이콘 32 `text.brand`
2. 제목 `heading-4` `text.primary` (아이콘 아래 `space.4`)
3. 설명 `body-sm` `text.secondary` 1~2문장 (제목 아래 `space.2`)
4. 주 액션 `primary md` 1개 (설명 아래 `space.6`), 보조는 링크

| 종류 | 제목 예 | 설명 | 액션 |
|---|---|---|---|
| 처음 (아직 없음) | "프로젝트가 아직 없어요" | 만들면 무엇이 좋은지 한 문장 | "첫 프로젝트 만들기" |
| 검색 결과 없음 | "‘{검색어}’ 결과가 없어요" | "다른 단어로 검색하거나 필터를 지워 보세요" | "필터 지우기" (secondary) |
| 필터 결과 없음 | "조건에 맞는 항목이 없어요" | | "필터 초기화" |
| 권한 없음 | "볼 수 있는 권한이 없어요" | "관리자에게 요청하세요" | "권한 요청" |
| 완료(할 일 0) | "모두 처리했어요" | 축하 한 마디 | 없음 또는 "보관함 보기" |

- 표·리스트 안 빈 상태는 컨테이너 안에서 높이 최소 240.
- 일러스트는 `brand.mist` `brand.ice` `blue.100` 3색 이내 라인 일러스트. 없으면 아이콘으로 충분하다.
- 빈 상태에서 '도움말 문서 보기' 같은 부차 링크는 하나까지.

## 3. 오류

| 수준 | 표시 | 예 |
|---|---|---|
| 필드 | 인풋 테두리 `border.danger` + 아래 `caption` `text.danger` + 아이콘 12 | "이메일 형식이 아니에요" |
| 폼 | 상단 danger 배너 + 각 필드 오류. 첫 오류 필드로 포커스 이동 | "3개 항목을 확인해 주세요" |
| 동작 | 토스트(오류, 8초) + 가능하면 "다시 시도" | "저장하지 못했어요 · 다시 시도" |
| 섹션 | 그 섹션만 오류 상태(아이콘 + 문구 + 다시 시도 버튼), 나머지 화면 유지 | 위젯 하나가 실패 |
| 페이지 | 빈 상태 형태 + 오류 코드 `caption` `text.tertiary` + "다시 시도" / "홈으로" | 500 |

문구 규칙
- **무엇이 안 됐고 → 왜 → 어떻게 하면 되는지** 순서. "오류가 발생했습니다" 만 쓰지 않는다.
- 사용자 탓하지 않는다: "잘못 입력하셨습니다" ❌ → "이메일 형식이 아니에요" ✅
- 기술 용어·코드는 `caption` `text.tertiary` 로 작게 뒤에(지원 문의용).
- 되돌릴 수 있으면 방법을 같이: "삭제됨 · 되돌리기".

## 4. 확인 다이얼로그

언제 띄우나: **되돌릴 수 없는 것**(삭제·탈퇴·전송·결제)만. 되돌릴 수 있는 건 바로 실행 + 토스트 "되돌리기".

| 요소 | 규격 |
|---|---|
| 폭 | `modal.width-sm` 400 |
| 제목 | `heading-2`, 질문형, 대상 명시: "‘디자인 시안 v3’ 를 삭제할까요?" |
| 본문 | `body-sm` `text.secondary`, 결과 한 문장: "삭제하면 복구할 수 없어요." |
| 버튼 | 취소(secondary) · 동작(primary 또는 danger). 동작 이름 그대로: "삭제" "탈퇴" "보내기". "확인/예" 금지 |
| 매우 위험 | 대상 이름을 입력해야 버튼 활성(저장소 삭제·계정 탈퇴) |
| 포커스 | 파괴 동작이면 **취소**에 첫 포커스, 아니면 동작 버튼 |

## 5. 성공 피드백

| 행동 | 피드백 |
|---|---|
| 저장(같은 화면 유지) | 토스트 "저장됨" 4초. 또는 버튼 라벨이 1.5초 "저장됨 ✓" 으로 |
| 만들기(다른 화면으로) | 이동 후 그 화면 상단 토스트 "‘{이름}’ 을 만들었어요" |
| 삭제 | 토스트 "삭제됨 · 되돌리기" 8초 |
| 복사 | 버튼 아이콘이 check 로 1.5초, 툴팁 "복사됨" |
| 토글·좋아요 | 즉시 반영, 토스트 없음 |
| 전송(메일·결제) | 성공 페이지 또는 success 배너(중요한 것은 토스트보다 오래 남겨야 한다) |

토스트로 "성공했습니다" 만 쓰지 않는다. 무엇이 됐는지 목적어를 넣는다.

## 6. 비활성(disabled) vs 숨김

- 조건이 곧 충족될 수 있으면 **비활성 + 이유**(툴팁·도움말): "항목을 선택하면 삭제할 수 있어요".
- 권한이 없어 영원히 못 쓰면 **숨김**. 비활성 버튼이 많은 화면은 권한 설계가 잘못된 것.
- 비활성 버튼에도 툴팁이 뜨도록 감싸는 요소에 툴팁을 건다(disabled 요소는 이벤트가 안 온다).

## 7. UX 문구 기본

- 어미는 프로젝트마다 한 가지로 통일: `-해요` 체(기본, 부드러움) 또는 `-합니다` 체(업무·공공). 한 화면에 섞지 않는다.
- 버튼은 **동사**: "저장" "삭제" "보내기" "만들기" "내보내기". "OK" "제출" "확인" 은 피한다(확인은 정보성 다이얼로그의 단일 버튼일 때만).
- 라벨은 명사, 짧게: "이메일" (❌ "이메일 주소를 입력하세요").
- 플레이스홀더는 예시: "예: hong@example.com".
- 숫자 표기: 천 단위 쉼표, 단위 붙여쓰기(2,400원 · 3개 · 16px), 날짜 `2026.09.18` 또는 `9월 18일`, 시간 24시간제 `14:30`. 상대 시간("3분 전")은 7일까지, 그 뒤는 날짜.
- 말줄임: 1줄 `text-overflow: ellipsis`, 여러 줄 `-webkit-line-clamp: 2`. 잘린 것은 툴팁이나 title 로 전체 제공.
