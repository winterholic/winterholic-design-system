# 03 · 간격·레이아웃 (여행가쟈)

## 1. 4px 스케일 (원본 --sp-1 ~ --sp-12)
| 토큰 | px | 언제 |
|---|---|---|
| `1` | 4 | 칩 내부 상하, 아이콘↔라벨 미세, 탭바 항목 gap, 도감 셀 내부 |
| `2` | 8 | 칩 사이, 탭바 패딩, 카드 안 세로 간격, 도감 셀 gap |
| `3` | 12 | 카드 안 요소 사이, 헤더 gap, 리스트 행 상하, 카드 좌우 패딩 |
| `4` | 16 | **기본**. 셸 안전 여백(모바일), 카드 상하 패딩, 리스트 좌우, 필드 사이 |
| `5` | 20 | BottomCta 좌우·상단, 태블릿 셸 여백 |
| `6` | 24 | 블록 사이, 프레임 패딩, 다이얼로그 패딩, BottomCta 하단 |
| `7` | 32 | 섹션 사이(모바일), 데스크톱 배경 패딩 |
| `8` | 40 | 데스크톱 셸 상단 |
| `9` | 48 | 섹션 사이(데스크톱), 셸 좌우, 빈 상태 상하 |
| `10` | 64 | 프레임 높이 여유 |
| `11` | 80 | 랜딩·안내 대형 여백 |
| `12` | 96 | 데스크톱 배경 격자 |

임의 px(13·15·27) 금지. 원본에서 4 그리드 밖 값은 셋뿐: 버튼 gap 6, 버튼 md 패딩 10/18, 입력 패딩 10. 토큰(`component.button.*`)으로 잠가 두었다.

## 2. 간격 원칙 — 종이 위의 여백
- 안쪽 패딩 ≤ 바깥 간격. 카드 패딩 16/12, 카드 사이 16 이상.
- 컴포넌트 사이는 부모 `gap`. 자식 `margin-bottom` 금지.
- 먹선(2px)이 경계를 이미 만든다. 먹선 있는 요소끼리는 8 이면 충분, 먹선 없는 요소끼리는 16.
- 세로 리듬 8·16·24·32 네 값.

## 3. 셸 — 모든 화면은 AppShell
```
[오방색 띠 6]
[헤더 52: 좌 뒤로/타이틀(Myeongjo 22) · 우 보조 아이콘 1개(44)]   padding-top 4
[본문 1fr 스크롤, 안전 여백 max(16, safe-area), 최대 430]
[BottomCta: 패딩 20/20/24 + safe-area, 최대 390]                  ← 네비 위 고정
[TabBar 플로팅: 홈·도감·마이, ink 2px r-lg]                       ← z 1150
```
- 모바일(≤767): 전폭. 본문 최대 430 가운데. 하단 여백 = 탭바 + 16.
- 태블릿(768 이상): 폰 프레임 셸 등장 — ink 2px, radius 32, `shadow.paper-lg`, 폭 min(100%, 1080), 높이 min(900, 100dvh − 64), 패딩 24, 안전 여백 20.
- 데스크톱(1024 이상): 책상 배경(hanji-2 + 빨강·먹 격자 96) 패딩 32, 프레임 안 셸 패딩 40/48/32, 탭바는 999 필 + faint 테두리로 플로팅.
- `tone="dark"`: 무대. 배경 `surface.stage`, 글자 hanji.bright, 띠 유지. 연출 화면만.
- `hideNav`: 온보딩·연출·공유. "닫기/건너뛰기" 링크를 직접 둔다(Bright Line 11).

### 기둥(컨테이너) — 한 화면은 기둥 하나만
| 토큰 | px | 언제 |
|---|---|---|
| `panel` | 520 | 폼·단일 카드(로그인·가입·방 만들기·다이얼로그) |
| `doc` | 720 | 읽는 문서(확률 안내·법적·안내). 본문·표·콜아웃이 같은 오른쪽 끝 |
| `wide` | 960 | 이미지·차트 섞인 안내 |
| `content` | 1152 | 목록·그리드 상한 |
| `phone` | 430 | 폰 프레임 안 본문 |
| `cta` | 390 | BottomCta 최대 |
실측(2026-08-15)에서 컨테이너 폭이 40종 흩어져 있던 게 데스크톱이 화면마다 달라 보이던 원인이었다. 새 숫자를 만들지 않는다.

### 브레이크포인트
`xs` 375(최소 보장) · `sm` 640 · `md` 768(프레임 셸) · `lg` 1024(책상 배경·필 네비) · `xl` 1280.

## 4. 화면 골격 공식

### 홈 (캡슐 중심)
```
띠 → 헤더(로고 · PullCounter 7/10 mono)
eyebrow(Cinzel) + 타이틀(Myeongjo 800, 밑줄 단청 그라데 3px)   ← 아래 16
캡슐 160×189 가운데, 부유(appCapsuleFloat), 가용 높이 ~40%      ← 아래 12
태그라인(Batang) + 붓글씨 강조 1곳                              ← 아래 24
인기 리스트(ListItem 56 × N 또는 카드 가로 스크롤)
GachaCta 52 하단 고정 → TabBar
```

### 리스트 (코스·방·최근 장소)
ListItem 56: [num mono 12] [icon 22] [title Myeongjo 17 / meta Batang 13] [우측 chevron]. 구분 hanji-dark 1px 또는 8 여백. 좌우 16.

### 그리드 (도감 3열)
셀 108 정사각, gap 8, 좌우 16. 375 = 16 + 108×3 + 8×2 + 16 = 372. 태블릿 4열, 데스크톱 프레임 안 4열(폭 430 기준 3열 유지가 안전).

### 카드 상세 (결과·도감 상세)
카드 200 가운데(무대에서는 `shadow.deep`) → 아래 등급 배지 + 지역명 heading-xl + 붓글씨 인용 → visitorNote mono-sm → BottomCta 2버튼(공유 blue / 코스 red).

### 폼 (로그인·방 만들기)
panel 520(모바일 전폭 − 32). 필드 사이 16, 라벨 위 4, 도움말 아래 4. 제출 = BottomCta 전폭 lg 또는 폼 하단 md 우측.

### 문서 (확률 안내·법적)
doc 720, heading-sm 섹션 사이 32, body 행간 loose, 표는 hanji-2 헤더 + hanji-deep 선, 콜아웃 = 한지 카드 + 파랑 띠.

## 5. 정렬
- 텍스트 좌측. 가운데는 홈 히어로·캡슐·빈 상태·결과 카드·온보딩만.
- 헤더: 좌 뒤로(44) 또는 타이틀, 우 보조 아이콘 1개까지(모노크롬).
- BottomCta Double: 좌 blue/ghost, 우 red. 같은 폭 1:1.
- 숫자(mono) 우측 정렬, PullCounter 는 헤더 우측.
- 캡슐·카드는 항상 가운데.
